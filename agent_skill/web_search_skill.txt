║  WEB SEARCH + DOWNLOAD SKILL                                     ║
║  Trigger: user asks to "search the web", "google this",          ║
║           "download <url>", "fetch a file from internet".        ║
╚══════════════════════════════════════════════════════════════════╝

Two parser actions are available:

    WEB_SEARCH: <query>                          # search the web
    DOWNLOAD:   <url> -> <absolute_path>         # fetch a file

Both are PARSER actions — do NOT wrap them in RUN_CMD or use python
directly. Output exactly one fenced code block, no prose.

═══════════════════════════════════════════════════════════════════
 WEB_SEARCH
═══════════════════════════════════════════════════════════════════

FORMAT
    WEB_SEARCH: <query>
    WEB_SEARCH: <query> | num=15

  - Default result count: 10. Max useful: 25.
  - Backend: DuckDuckGo HTML via lynx (no API key, no rate limit
    headaches).

EXAMPLE 1 — simple search
-------------------------
    WEB_SEARCH: python asyncio tutorial

EXAMPLE 2 — more results
------------------------
    WEB_SEARCH: best android terminal emulators 2024 | num=15

OUTPUT you'll receive
---------------------
    🔍 N results for: <query>

    1. Title
       🔗 https://url
       Snippet text ...

    2. ...
    ...

═══════════════════════════════════════════════════════════════════
 DOWNLOAD
═══════════════════════════════════════════════════════════════════

FORMAT
    DOWNLOAD: <url> -> <absolute_path>
    DOWNLOAD: <url> -> <absolute_path> | overwrite=true

  - Path MUST be absolute (/sdcard/... or /data/data/com.termux/...).
  - Streams live progress into the terminal box (bytes/total/percent).
  - If the file already exists and overwrite isn't true → error,
    and you should retry with overwrite=true (or pick a new path).
  - Downloads run in the background; polling shows live chunks.
  - User can Kill at any time — you'll get a "🛑 User ne Kill button
    dabaya" final output.

EXAMPLE 1 — plain download
--------------------------
    DOWNLOAD: https://example.com/file.zip -> /sdcard/Download/file.zip

EXAMPLE 2 — overwrite existing
------------------------------
    DOWNLOAD: https://example.com/file.zip -> /sdcard/Download/file.zip | overwrite=true

═══════════════════════════════════════════════════════════════════
 COMBINED WORKFLOW (search → pick → download)
═══════════════════════════════════════════════════════════════════

1) Search:
       WEB_SEARCH: termux vim cheatsheet pdf

2) Read results. Pick the best URL.

3) Download:
       DOWNLOAD: https://best-site.com/cheatsheet.pdf -> /sdcard/Download/cheatsheet.pdf

4) Confirm file:
       FILE_INFO: /sdcard/Download/cheatsheet.pdf

═══════════════════════════════════════════════════════════════════
 RULES
═══════════════════════════════════════════════════════════════════

  [ ] Only ONE action per response.
  [ ] Only ONE fenced code block, no prose around it.
  [ ] Paths absolute.
  [ ] For DOWNLOAD, if file exists → retry with overwrite=true.
  [ ] After download, verify with FILE_INFO if user cares about size.
  [ ] For WEB_SEARCH, don't ask user "should I search?" — just do it.

═══════════════════════════════════════════════════════════════════
 BEHIND THE SCENES
═══════════════════════════════════════════════════════════════════

  WEB_SEARCH block
        ↓
  script.js parser → POST /search
        ↓
  web_search.search() in agent_skill/web_search.py
        ↓
  lynx -dump https://html.duckduckgo.com/html/?q=...
        ↓
  parse titles/urls/snippets → JSON
        ↓
  formatted output → AI

  DOWNLOAD block
        ↓
  script.js parser → POST /download
        ↓
  web_search.download() streams from URL to path
        ↓
  live progress pushed into /poll chunks
        ↓
  client terminal box shows streaming progress
        ↓
  final output → AI
